# 見張りの確認（ログを貼ってもらわずに済ませる）

定期の自動更新（update_rankings.yml。だいたい朝と夜の1日2回）の最後に、見張りが5本走る。
その結果をKeiがコピーして貼らなくて済むように、こちらで取ってきてまとめる。
**読むだけ。** 直す必要があるものを見つけても、勝手に直さず「直してよいですか」と聞く
（CLAUDE.md の「絶対に守ること」はそのまま守る）。

## 1. ログを取る
```
python3 .claude/skills/mihari/fetch_watch_log.py        # いちばん新しい定期実行
python3 .claude/skills/mihari/fetch_watch_log.py 2      # 1つ前（比べる用）
python3 .claude/skills/mihari/fetch_watch_log.py --id <実行番号>
```
- 「⏳ まだ走っています」と出たら、そのとおりKeiに伝え、終わる見込みの時刻を添える（1回およそ25分）。
- 中身は見張り5本：県予選mdと出典の突き合わせ／県1部の鮮度／参入戦の出場権／順位表と試合一覧の矛盾／取得元。
- **鮮度が赤で終わると、そのあとの3本（参入戦・矛盾・取得元）は走らない。**
  「走っていません」と出たら、それは異常ではなく赤の巻き添え。報告ではそう書く。

## 2. 前の回と比べる
必ず1つ前の回（引数 `2`）も取り、**変わったところ**を拾う。
- 赤・黄に新しく入った県、消えた県
- 「〇日から△日」の日数が増えて、あと少しで赤になる県（「※3日続いたら赤」）
- 台帳の期限（「期限 2026-11-03」など）が3日以内、または切れたもの
- 突き合わせの ⚠ の件数の増減と、その中身
- 参入戦の「確定 n / 16」の増加と、「参入戦ページの表と一致」かどうか

## 3. 宿題を突き合わせる
メモリの `mihari-homework.md` を読む（Kei と約束した「次の回で確かめる」ことの一覧）。
1つずつ実物（ログ、必要なら data/ のJSONや `?nocache=` の公開ページ）で確かめる。
済んだものはその行を消し、まだのものは残す。新しく約束したものは書き足す。

## 4. Keiへの報告の形（素人にわかる言葉で・短く）
```
見張り（10/30 夜の回）：赤 0 ／ 黄 43（うち新顔 0）／ 突き合わせ ⚠1

■ 対応が要るもの
  （無ければ「ありません」）
■ 前回から変わったこと
  ・富山：取得失敗が消えました（新しい窓口で取れています）
■ 宿題の確認
  ・山形 城北2-0山南 → 入りました（80試合）
■ 様子見でよいもの（毎回同じなので1行ずつ）
  ・大阪：協会サイト停止中（台帳の期限 11/3）
```
- 黄43件を全部並べない。「手動取り込みが止まっている」「消化数が変わっていない」の
  いつもの黄は、件数だけ書く。変わったものだけ名前を出す。
- 赤があれば、何が起きていて、こちらで直せるか（直せないなら台帳で黄にするか）を書き、
  「調べてよいですか」で止める。
- 実行番号のリンクを最後に1行付ける。
