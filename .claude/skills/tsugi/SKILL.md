# 次の依頼（未処理の依頼文を拾う）

運営フォルダ `~/Documents/Claude/Projects/u18-soccer.com運営/` の直下にある
「依頼」「指示書」を名前に含む .md が対象（`Coworkへの依頼_…` は Cowork の仕事なので除く）。
済んだかどうかは、**ファイルの1行目の印**で見分ける。

```
> 済 2026-10-30 c30bb2555（Claude Code）ひとこと
> 見送り 2026-10-30（Claude Code）理由
```

## 1. 一覧を出す
```
python3 .claude/skills/tsugi/list_requests.py             # 直近14日・印の無いもの
python3 .claude/skills/tsugi/list_requests.py --days 30
python3 .claude/skills/tsugi/list_requests.py --all       # 全期間（2026-10-15以前は印を付けていない）
```
- 2026-10-30 に、10/16〜10/28 の32本をコミット記録と1本ずつ照らして「済」にした。
  10/15以前の234本は印を付けていない（大半は片付いているはず）。`--all` で出てきても未処理とは限らない。
- Keiには、新しい順に「日付・題名・ひとことで何をする依頼か」を見せる。
  同じ話の依頼文が2本あれば（後から出た方が前のをまとめ直している等）、そう書く。

## 2. 印の無いものが本当に未処理か確かめる
印を付け忘れただけのこともある。取りかかる前に必ず確かめる。
```
git log --since=<依頼日の前日> --format='%h %ad %s' --date=short | grep -v chore:
```
- 依頼の中身に当たるコミットがあれば「もう済んでいました（コミット番号）」とKeiに伝え、印を付ける。
- コミットが無ければ未処理。Keiに「どれから進めますか」と聞く（Keiが選ぶ。勝手に始めない）。

## 3. 取りかかる
依頼文を全部読み、`/kokai` の手順で進める（コピーで試す→承認→コミット→push→実物確認）。
依頼文と実物が食い違ったら、勝手に直さず報告。

## 4. 済んだら印を付ける
push して実物を確かめたあとで付ける。
```
python3 .claude/skills/tsugi/list_requests.py --mark <ファイル名> 済 <コミット番号> [ひとこと]
python3 .claude/skills/tsugi/list_requests.py --mark <ファイル名> 見送り - <理由>
```
- コミットが複数なら `abc1234,def5678` のようにカンマでつなぐ。
- **見送り**はKeiが「やらない」と決めたときだけ。理由を短く書く。
- 一部だけ済んで残りがKeiの判断待ち、のときは印を付けず、残りをKeiに伝える。
- 印は1行足すだけ。依頼文のほかの行は変えない。ファイルの削除・移動はしない。
