# 公式の山順でトーナメント表を出す手順

対象のmdファイルは `data/tournaments/<大会>-2026/<県>-<大会>-2026.md` です（例：`wakayama-senshuken-2026.md`）。
表を描くのは `scraper/generate_prefecture_pages.py` です（関数 `_render_ordered_base_bracket`、`_render_staircase_from_rounds`、`_bracket_canon`）。
CLAUDE.md の「絶対に守ること」はすべてそのまま守る（生成はコピーで、add は個別、--force は使わない、push前に承認を取る）。

## 0. 表が出せない県を探す（頼まれたとき）
- 本番またはコピーで生成した `prefectures/*/index.html` を使う。`check_bracket.py` で「表=なし」の大会を挙げる。
- 試合がまだ1つも無い大会は、セクションごと出ない（仕様）。見つからなくても異常ではない。

## 1. 公式の組み合わせ表を探す
- 出典は**県サッカー協会**か**県高体連サッカー専門部**の公式PDFまたは画像に限る。
  ニュースサイトや学校のSNSの画像は、元の表を探す手がかりにだけ使う。
- 載っていないときは推測で並べない。Keiに「公式の表が見つからない」と報告して止める（山口のときはそうした）。
- PDFの2ページ目以降を画像で見るとき（qlmanage は1ページ目しか出せない）：
  `swift .claude/skills/tournament-bracket/pdfpage.swift 表.pdf ページ番号 出力.png 2400`
  出力した画像を Read で開いて読む。小さくて読めないときは数字を大きくする。
- 表の**上から順**（左の山を上から下へ → 右の山を上から下へ）に、試合とシード校の位置を書き出す。

## 2. md に山順を書く
土台にするのは、**全試合で両校が決まっている、いちばん早い回戦**です（ふつうは1回戦）。見出しのすぐ下に次のように書く：

```
## 1回戦（10/17）

<!-- 山順: 公式組合せ表（〇〇県サッカー協会「…」PDF）の上から順（左の山→右の山）。シード＝2回戦から／シード2＝3回戦から。並べ替えないこと -->
<!-- シード2: 四日市中央工業 -->
- 暁 vs 神戸
- 津東 vs 桑名
<!-- シード: 津 -->
- 四日市四郷 vs 久居
```

- `<!-- 山順: … -->` は、見出しの直後、その回戦の最初の試合行より**前**に置く（後ろに置くと効かない）。出典名を必ず書く。
- 試合行は、公式表と同じ順に**並べ替える**。スコアが入っている行は文字を変えずに、行の位置だけ動かす。
- シード校は、公式表でその学校が入る位置に置く。
  - 次の回戦から出る学校は `<!-- シード: 校名 -->`、2回戦あとから出る学校は `<!-- シード2: 校名 -->`、3回戦あとは `<!-- シード3: 校名 -->`。
- **校名の最後の「高」に注意**：表では最後の「高等学校」「高校」「中等教育学校」「高」を外して名前をそろえる。
  - 名前が1文字だけ残るとき（日高→日）は外さないように直した（2026-10-19）。
  - 「〇〇高」がそれ自体で校名の学校が、2文字より長い名前で出てきたら、表示を確認する。
- 後ろの回戦の `- A vs B` 行は、ボットが koko から埋めていく。手で書いたスコアをボットは上書きしない。
  - koko のカードを止めたいときは `<!-- 無視: A vs B -->` を書く。

### 表を描く部品が対応している大きさ
- シード2以上がある大会と、「試合数＋シード数」が16か32の大会は、階段状の部品（`staircase_bracket`）で描く。
- それ以外は「試合数＋シード数」が8か4のときだけ描ける。
- この条件に合わない大きさ（兵庫の32枠のとき）は表が出ない。コードを足す必要があるので、Keiに相談してから直す。

## 3. コピーで確かめる（リポジトリでは絶対に生成しない）
```
S=<scratchpad>
rm -rf $S/bf $S/af
rsync -a --exclude .git ./ $S/af/
rsync -a --exclude .git ./ $S/bf/
git -C . show HEAD:<変えたmd> > $S/bf/<変えたmd>        # 変更前に戻す（変えたファイルごとに）
(cd $S/bf && python3 scraper/generate_prefecture_pages.py >/dev/null; echo $?)
(cd $S/af && python3 scraper/generate_prefecture_pages.py >/dev/null; echo $?)
diff -rq -x __pycache__ $S/bf $S/af          # 変わるのは対象の県ページ（と変えたmd・py）だけのはず
python3 .claude/skills/tournament-bracket/check_bracket.py $S/af/prefectures/<県>/index.html $S/bf/prefectures/<県>/index.html
```
次のことを確かめる：
- 表が「あり」になっている。
- 校名の数が、出場校の数と同じ。
- 校名が途中で切れていない（「日」のようになっていない）。
- 全試合一覧（`<li>`）が「変化なし」。
- 回戦の名前（1回戦〜決勝）がおかしくない。「ラウンド1回戦」のような重なりがあれば、`_render_staircase_from_rounds` の回戦名の正規表現を確かめる。
- 見た目も見たいときは、`$S/af` で `python3 -m http.server` を立て、headless Chrome でスクリーンショットを撮る。
  長い校名が右端で切れていないかも見る。

## 4. Kei に報告して承認を取る
- やさしい日本語で、県ごとに次のことを書く：出典（どの団体の何という表か）、チーム数、シード校とどこから出るか、気になった点。
- 見つけたけれど手を付けなかったことは、別の項目に分けて書く。
- `git status` を見せ、add するファイル名とコミット名（例：「選手権予選の和歌山・鹿児島に公式の山順を付けてトーナメント表を表示」）を書いて、「push してよいですか？」と聞く。
- `.claude/settings.local.json` と「医学コラム執筆プラン_2026年秋冬.md」は add しない。

## 5. push と反映の確認
1. `git fetch` → `git log HEAD..@{u}` を見る。ボットのコミットが先に入っていれば `git pull --rebase --autostash` で取り込む。
2. 対象ファイルだけを `git add` し、commit して push する（末尾に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`）。
3. `gh run list` で Actions を待つ。
   - 自分のコミットの「pages build and deployment」が cancelled になるのは、続くボットのコミットの公開に置き換わったためで、問題ない。
   - そのボットのコミットの公開が成功していればよい。
   - 「in progress deployment」で失敗していたら `gh run rerun <id> --failed` で再実行する。
4. `curl -s "https://u18-soccer.com/prefectures/<県>/?nocache=<日付>"` を保存し、`check_bracket.py` で表と校名の数を確かめて報告する。
